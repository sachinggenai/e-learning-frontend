## Work Done Today

### Problem 1 — "Text Content" template not visible in Add Page dialog

**Root cause:**  
`TemplateSelector` has two data paths:
- `vmTemplates` (from `state.rawTemplates`) — used when backend returns any templates
- `templates` (legacy) — used only as fallback when `rawTemplates` is empty

The static `content-text` entry was only injected into the `legacy` array inside `fetchTemplates`. When the backend returns other templates, `rawTemplates` is non-empty so `vmTemplates` is used — and `content-text` was invisible.

**Fix:**  
`src/store/slices/courseSlice.ts` — `fetchTemplates` thunk now injects the static `content-text` DTO into **both** `backendTemplates` (raw) and `legacyList`, so both paths show it.

```ts
const rawStaticEntry = {
  id: "content-text", templateId: "content-text", type: "content-text",
  name: "Text Content", title: "Text Content",
  description: "Paste or type HTML content into a clean, full-page layout.",
  category: "content-presentation", order: -1, fields: [],
  data: {
    content: { title: "", content: "<p>Enter your content here...</p>" },
    description: "Paste or type HTML content into a clean, full-page layout.",
    category: "content-presentation",
  },
};
backendTemplates.unshift(rawStaticEntry);
legacyList.unshift(staticEntry);
```

**Test updated:**  
`src/store/slices/courseSlice.serviceLayer.test.ts` — updated assertion to check `payload.raw[0]` contains the injected entry.

## Architecture Quick Reference

### Template Dialog Flow
```
PageManager (PageManager.tsx)
  └── opens TemplateSelector (TemplateSelector.tsx)
        ├── dispatches fetchTemplates(courseId) → courseSlice.ts
        │     └── courseService.listAvailableTemplates() → backend API
        │           + injects static content-text into raw + legacy
        ├── reads state.rawTemplates → mapTemplateList() → vmTemplates (preferred)
        ├── falls back to state.templates (legacy) if rawTemplates empty
        ├── JS filter: DEMO_VISIBLE_TYPES.has(type) must pass
        └── renders .template-card[data-template-type="..."] per template
              └── TemplateSelector.css DEMO MODE block hides non-demo cards
```

### "Add Component" Dialog (separate from Add Page)
```
ComponentList.tsx → ComponentPicker.tsx
  └── reads from ComponentRegistry (local, self-registered)
  └── registrations.ts populates registry on import (imported in App.tsx)
```
These are two different dialogs. The demo filter applies only to `TemplateSelector`.

### content-text Field Convention
- **Canonical field:** `data.content` (HTML string) — backend, SCORM renderer, editor
- **Legacy fallback:** `data.body` — still read for backward compat, never written
- **SCORM renderer:** `contentRenderer.ts` reads `component.data.content`

### SCORM Export Runtime
- `src/export-runtime/core/runtime.ts` — entry point, `createExportRuntime()`
- `src/export-runtime/core/rendererRegistry.ts` — registers all renderers
- `src/export-runtime/renderers/` — one file per renderer or logical group
- Missing renderer → `renderUnsupportedComponent()` (safe fallback, but not useful)
